通用内容读取层 · Agent Skill + CLI + MCP

把一个链接，真正读成 AI 能用的内容。

x-reader 是给 AI Agent 用的 Universal Content Reader。你丢给它一个 X、网页、YouTube、B站、播客、微信公众号、小红书、Telegram、RSS 或其他网页链接，它负责识别来源、走正确的读取链路，再把内容统一整理成 Agent 可以继续研究、总结和自动化处理的结构化结果。

一个 Reader，处理不同来源

不要让每个 Agent 都自己再拼一套 scraper。

Agent 只需要把 URL 交给 x-reader。平台识别、不同 fetcher、fallback、结构化输出这些脏活由 reader 层处理，上层拿到的是统一的内容对象，而不是一堆平台特例。

产品本体

先把来源读出来，再谈证据覆盖。

Evidence Receipt 是 reader 上面的可信度机制，不是 x-reader 本身的定义。x-reader 的第一职责，是把不同平台的原始来源真正变成 Agent 可消费的内容。

01
读取原始来源

针对不同平台走不同读取链和 fallback，把 URL 变成实际正文、metadata 或媒体内容。

02
统一成 Agent 可用结构

标题、URL、来源类型、正文和相关 metadata 被整理成统一 payload，而不是让上层自己适配每个平台。

03
需要时继续读媒体

视频、音频如果影响结论，就继续进入字幕、transcript 或转录链，而不是停在 caption / description。

Evidence-aware 是护栏

它还会告诉 Agent：这次到底读完整没有。

这层能力负责防止搜索摘要冒充原文、推文正文冒充附件视频、视频简介冒充口头内容。它增强 reader 的可信度，但不是把 x-reader 变成一个“AI 查错工具”。

PASS任务真正需要的来源层已经读取。
PARTIAL已经拿到有用内容，但仍缺会影响结论的关键层。
FAIL无法可靠获取用户要求的原始来源。
UNKNOWN当前材料不足以确认是否覆盖了目标来源。

它不是什么

不是另一个摘要器，也不只是“检查 AI 有没有撒谎”。

摘要和分析发生在读取之后；Evidence 状态只是告诉上层这次读取到哪。真正可复用的产品资产，是前面那层跨平台 source ingestion / universal reader。

读一个公开链接使用完整版本
最简单的理解方式

给 Agent 一个 URL，剩下的来源读取交给 x-reader。

跨平台一个入口，输出 Agent 能继续使用的结构化内容；缺什么，再明确告诉上层缺什么。
